# seminar-attribution

研讨会收入归因分摊库（Go，纯内存，无外部依赖）。上层将一个完整统计批次的
已成交商机传入 `Allocate`，得到确定性的整数美分分摊结果，并从同一份结果
派生完整批次报表、单笔商机视图与选定研讨会汇总。

## 业务规则

- 每笔商机有唯一稳定标识、非负整数美分金额、1 至 10 个不同的影响研讨会。
- 等权归因：理论归因额 = 成交金额 ÷ 关联研讨会数量。
- 实际分摊为整数美分：每条关联项取理论值的向下或向上取整；
  每笔商机的分摊合计精确等于成交金额。
- 每场研讨会的实际汇总等于其精确理论汇总（有理数）的向下或向上取整；
  理论汇总恰为整数时必须等于该整数。逐笔守恒与逐场边界同时成立。
- 结果确定：同一输入集合结果唯一，与商机顺序、关联研讨会顺序无关。
- 筛选只影响展示，不会把被隐藏研讨会的收入重新分给剩余研讨会。

## 用法

```go
deals := []seminarattribution.Deal{
    {ID: "d1", AmountCents: 1, SeminarIDs: []string{"A", "B"}},
    {ID: "d2", AmountCents: 1, SeminarIDs: []string{"B", "C"}},
    {ID: "d3", AmountCents: 1, SeminarIDs: []string{"A", "C"}},
}
res, err := seminarattribution.Allocate(deals)   // 分摊（确定性）
full := res.FullReport()                          // 完整批次报表
deal, err := res.DealReport("d1")                 // 单笔商机视图
subs, err := res.SeminarReport("A", "C")          // 选定研讨会汇总
```

三种视图共享同一份分摊结果；`SeminarSummary` 同时给出精确理论汇总的
下/上取整边界（`TheoreticalFloorCents` / `TheoreticalCeilCents`），便于对账。

## 算法概述

1. 排序归一：商机按 ID、关联研讨会按 ID 排序，使结果与输入顺序无关。
2. 精确理论值：金额 `A`、关联数 `k` 时，`A = k·q + r`（`q` 为商、`r` 为余数）。
   每条关联项的理论值为 `q + r/k`；研讨会理论汇总的小数部分以 1/2520
   （1..10 的最小公倍数）为单位精确累加，全程整数运算，无浮点误差。
3. 整数分摊：把“`r` 个 1 美分单位分给哪些关联研讨会”归约为带下界的
   最大流问题（Dinic 算法）——每笔商机必须分出 `r` 个单位，每条关联边
   容量 1，每场研讨会的接收量落在理论汇总边界之内。分数解恒可行，
   故整数可行解必存在；建图顺序固定，算法结果确定。

## 运行测试

```sh
go test ./...        # 全部测试（含满规模性能测试）
go test -run TestScale -v ./...   # 只跑规模测试，查看耗时与峰值内存
```

满规模测试（50000 笔商机、5000 场研讨会、300000 条关联、单笔最高
1e12 美分）在本机实测：分摊 + 完整报表约 0.1 秒（限制 20 秒），
峰值堆内存约 79 MiB（限制 256 MiB），并用 `math/big.Rat` 独立精确核对
每条关联项取值范围、每笔守恒与每场汇总边界。
